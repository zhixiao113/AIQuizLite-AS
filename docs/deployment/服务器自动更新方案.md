## 建议的发布与回滚设计

GitHub Actions 先执行适用的发布器测试、Android 单元测试、lint、构建与签名/版本校验。只允许受保护的发布分支、tag 或手动批准的 production 环境发布；PR 测试不得获得生产凭据。部署串行执行，防止两个版本互相覆盖。

第一阶段可继续在本机用原密钥签名，并发布核验后的 GitHub Release。Actions 监听正式 Release 或受控手动触发，下载并核对 APK、清单、哈希和签名后部署。这样服务器与 Actions 暂不需要保存 Android 私钥。若以后要求 GitHub 自动签名构建，再配置受保护环境的签名 Secrets；本机 DPAPI 文件不能直接用于 Linux CI。

服务器目录按版本保留，例如 `/srv/aiquizlite/releases/<code>-<hash>/`；先上传到 staging，校验完整性和版本合法性，通过后原子切换 `current`，同时记录 `previous`。这是方案示例，实际路径须确认。

Nginx 对外提供可信 HTTPS、更新清单和 APK。APK 使用不可变的版本/哈希 URL，旧 URL 在切换后仍可访问，避免进行中的下载中断。清单不缓存；APK 可长期缓存。不应只让 APK 路径依赖 `current` 而使旧下载链接突然失效。

切换后执行真实域名 HTTPS 健康检查，检查清单内容、APK HTTP 状态及哈希。上传、校验或切换失败需返回失败状态，写入服务器部署日志，并留存 Actions 日志/失败产物；切换后检查失败则原子恢复 previous 并复查。手动回滚流程选择已保存的发布版本，完整记录版本、commit、时间、失败步骤和回滚结果，不记录密钥。

Nginx 配置通常固定，不需每次 APK 发布 reload；确有配置更改时，先 `nginx -t`，再 reload。Nginx 的配置检查不能代替发布包健康检查。

至少保留当前和上一个成功版本。回收策略另行确认，不能删除清单或在途下载仍依赖的文件。自动回滚仅恢复服务器发布状态；已安装新版 APK 的 Android 设备不会自动降级。发现应用自身 bug，仍需更高 versionCode 的同签名修复版本，不能保证一次发布对所有设备绝无影响。

应用迁移需把当前 SakuraFrp 地址切换到服务器 HTTPS 地址，并取消历史宽松 TLS 校验；本地备用更新方式仍保留。若需手机同时选择服务器/本地备用源，作为独立客户端改动确认后实现并升级版本。

## 请提供或确认

1. 服务器公网 IP、Linux 发行版/版本、CPU/内存/磁盘可用空间、SSH 端口；建议使用专门的非 root 部署用户，并限定目录权限及确有必要的 sudo 操作。
2. 更新域名、DNS 控制权/解析状态；80/443 的安全组与防火墙状态。是否已有 Nginx、面板、Docker 或其他网站，避免覆盖既有配置。
3. 确定发布目录、预计下载量/带宽、旧版本保留数量、日志保留时间；SSH 主机指纹须通过可信渠道核验。
4. 用部署专用 SSH 公钥授权，不发送 root 密码或私钥到聊天。Actions 的 SSH 私钥放 production Environment Secrets；告知配置完成即可。
5. GitHub 使用现有 `zhixiao113/AIQuizLite-AS` 还是其他仓库；开启 Actions，确认发布触发条件和 production 审批人。当前已连接账号具备 admin 权限，Git 推送使用本机既有登录，不需要在聊天索取 GitHub 密码或 PAT。
6. 工作流默认 `contents: read`；创建 Release 的任务才增加 `contents: write`。编辑工作流若使用个人令牌，需要该仓库 Contents/Workflows 写权限；设置 Secrets/环境及保护规则需要相应仓库管理权限。优先使用工作流自带的短期 GITHUB_TOKEN，避免长期全仓库令牌。
7. 选择“本机签名后 Release 自动部署”或“GitHub 自动构建并签名”。后者再按受保护环境要求配置原 keystore 和两项密码 Secrets，不能上传证书到公开仓库。

参考：[GitHub 工作流认证与最小权限](https://docs.github.com/en/actions/tutorials/authenticate-with-github_token)、[GitHub Secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)、[Nginx 参数与配置检查](https://nginx.org/en/docs/switches.html)。
