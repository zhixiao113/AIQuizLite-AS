# AI 讲解缓存与多 AI 分工（2026-11-04）

## 交付行为

- 练习与模拟考试复盘统一使用 `AiExplanationDialogLauncher`。
- 相同题目内容、标准答案和作答内容复用讲解；选择题选中顺序、选项显示顺序、连线操作顺序不再导致重复生成。填空顺序、题目内容、图片引用、标准答案和作答结果变化会产生新缓存。
- 更换模型/Key 不自动废弃讲解。已有缓存可以在未配置 Key 时查看；用户点“重新生成”才主动替换。生成失败保留旧缓存，“重试”延续原请求意图。
- 同题进行中的请求合并，不同题可独立执行。关闭窗口或离开 Activity 只结束等待，后台成功结果仍保存；强制结束应用/系统回收进程时未完成请求不能保证完成。
- 原版本纯文字缓存按旧键尽量读取并迁移。旧版本图片题讲解没有实际看图，不迁移为新版图片讲解。

## 混合方案与配置

1. 保存多个兼容 OpenAI Chat Completions 接口的 AI 配置，各自独立设置名称、HTTPS 地址、模型和 Key。
2. AI 可分别启用/停用，指定一个“文字讲解”模型和一个“图片理解”模型；也允许同一配置承担两种分工。
3. 纯文字题直接调用文字模型；有图题先读取本地题图与解析图，按顺序发送给图片模型，再将图片描述交给文字模型输出结构化讲解。
4. 图片模型未配置/停用、图片读不到、接口失败时明确提示并停止，不降级为盲猜讲解。配置的模型本身必须支持图片；文字连接测试只证明基础接口连通。
5. 图片通过 `image_url` data URL 发送，支持 PNG/JPEG/GIF，总源数据上限 12 MiB；图片理解服务会收到题目资料和图片。协议参考：[官方 Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

Key 使用既有 Android Keystore AES/GCM 加密并保存于排除系统备份和学习备份的 `ai_config`。原有单配置自动作为“原有 AI”兼容。空 Key 只在地址相同时保留，更换地址要求重填。编辑目标和非密钥草稿支持重建恢复，未保存 Key 仅在旋转时保留于内存，不放入 Bundle。

支持添加、切换、重命名、删除和批量粘贴导入；切换/返回时提示保存或放弃草稿。批量导入一次 1–20 条，最多保留 50 个配置，输入限制 128K 字符。先验证完整数组，再加密暂存并统一注册；错误信息不回显 Key。

```json
[
  {"name":"文字讲解","baseUrl":"https://text.example.com/v1","apiKey":"填入自己的Key","model":"填入文字模型名称","enabled":true,"text":true},
  {"name":"图片理解","baseUrl":"https://vision.example.com/v1","apiKey":"填入自己的Key","model":"填入视觉模型名称","enabled":true,"vision":true}
]
```

示例地址和模型是占位符。导入添加新配置，只有显式指定的分工会替换现有选择，不导出凭据。

## 安装后验收

1. 保留原题库/进度覆盖安装；在 AI 设置检查原配置保留，添加图片服务并指定分工。
2. 纯文字题生成一次，关闭重开、退出页面、重启应用后再次打开，应显示已缓存且不再请求；更换模型后仍可查看。
3. 连线题按不同顺序建立相同关系，再次查看讲解应复用。
4. 图片题应先调用图片服务再调用文字服务；缺少图片配置时提示设置；故意填错图片 Key 后不应生成无图讲解。
5. 有缓存时让文字服务失败，点重新生成→重试应再次请求；恢复网络后成功替换。
6. 添加两套配置后分别启停、切换、编辑/放弃、旋转和批量导入，检查配置与分工互不串用。
