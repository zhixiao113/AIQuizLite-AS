# 本地更新方法

## 实现与状态（2026-10-11）

2026-10-12 补充：本文保留本地实现及开发操作记录。1.1.4/code15 起正式用户 App 固定使用 GitHub 在线更新，不展示更新源；本地方式用于开发者调试、文件准备和旧客户端迁移，下面的旧客户端地址/手机检查步骤不代表新版会访问本地服务。HTTPS 宽松信任已在 1.1.3 移除，不允许为调试全局绕过证书验证。

本地在线更新由原证书签名的 APK、Python 静态更新服务、SakuraFrp 隧道和 Android 更新客户端组成。保留此方式，后续服务器部署不得删除这些脚本或更换应用签名。

流程：原证书构建 → 校验真实 APK → 准备更新清单与不可变 APK 文件 → 本机 HTTP 服务 → 已有 SakuraFrp 隧道 → 手机检查更新、下载、校验并覆盖安装。

- `scripts/configure-release-signing.ps1`：用交互密码输入生成当前 Windows 用户专用的 DPAPI 加密配置。
- `scripts/build-device-release.ps1`：运行发布器测试、Release lint/单元测试/构建，验证原证书后准备本地更新文件；不启动服务器和隧道。
- `update_server.py`：用 Android SDK 的 aapt2/apksigner 读取并验证真实包名、版本、唯一签名。先放置带版本和哈希的 APK，最后原子替换 `version.json`；校验失败保留原清单，已发布的旧 APK 不主动删除。
- `启动更新服务器.bat`：进入项目目录，设置 UTF-8，启动发布器和 `127.0.0.1:4387` 的 HTTP 服务；重复启动检测既有服务，不要求重新构建。
- `UpdateChecker` / `UpdatePackageRules` / `UpdateDialog`：手机端检查版本、下载完整性和安装兼容性，调用系统安装器，不能绕过系统签名规则。

BAT 默认选择顺序：当前 `artifacts/device-release-vN/outputs/apk/release/app-release.apk` → 同版本 `update-server/version.json` 指向的已准备包 → 手动 Android Studio 输出 `app/release/app-release.apk`。显式 `--apk` 优先，所有路径都必须重新校验。

## 需要保留的资料

- Windows、可用 Python 3、Java 17 或兼容的 Android Studio JDK、Android SDK 35 及 build-tools；SDK 位置由本机 `local.properties` 的 `sdk.dir` 或环境变量提供。
- 原 `../app_sign.jks`，别名 `key0`。证书 SHA-256：`6973568484920238d35d94425c70601210ca2eaf7e728326785b66fb7e9576c8`。
- 本机 `.local-signing/release-passwords.json`；密码由 Windows DPAPI 加密，仅当前电脑和用户可解密，换电脑需重新交互配置。
- 已有 SakuraFrp 启动器与 `mcMC` 隧道：公网 TCP 41717 → `127.0.0.1:4387`。当前应用内置地址为 `https://frp-dad.com:41717`。

密钥文件、密码、本机配置和更新输出均不提交版本库。仓库只保留脚本及已签名 APK，不包含签名私钥。

## 发布新的验收版本

1. 代理检查已发布版本，并同时提高 `app/build.gradle` 的 `versionCode` 和 `versionName`。已对外发布的 code 不重复使用；失败且未发布的构建可重试。
2. 新电脑首次配置：

   ```powershell
   ./scripts/configure-release-signing.ps1
   ```

3. 构建并准备更新：

   ```powershell
   ./scripts/build-device-release.ps1 -Notes '本次更新说明'
   ```

   产物为 `artifacts/device-release-vN/outputs/apk/release/app-release.apk`，清单为 `update-server/version.json`。构建输出若需留档，可从本机终端保存到 `artifacts/`，不要把凭据记录到日志。

4. 开启既有 SakuraFrp 隧道，双击 `启动更新服务器.bat`。第一次启动应出现监听信息；已有服务时只更新文件并提示已在运行。
5. 检查本机清单：

   ```powershell
   Invoke-RestMethod http://127.0.0.1:4387/version.json
   ```

6. 再检查公网清单及清单对应的 APK。公网访问必须单独验证，不能用本机 HTTP 200 代替。不要通过禁用 TLS 检查把失败当作通过。
7. 手机「设置 → 检查更新」下载并覆盖安装。先确认新版本号、题库与进度保留，再完成连线、字体、专项练习、导入导出及备份等验收。不得主动卸载用户现有应用。

仅准备文件、不启动服务：

```powershell
python update_server.py '本次更新说明' --apk app/release/app-release.apk --prepare-only
python -m unittest discover -s tests -p test_update_server.py -v
```

已准备的同一版本只需重新打开 BAT；无需重跑“新版本构建”脚本，其防重复 code 检查会拒绝重复交付。

2026-10-12 最新备用同步：1.1.8/code19 操作反馈优化包已通过受保护云端原证书发布。实际公开包复验后同步到代理 v19 目录、仓库包及 `update-server/AIQuizLite-v19-c4c575587e3f89f5.apk`；4,987,021字节，SHA-256 `c4c575587e3f89f5b6c40805572af92703e5233efaf3da89b00c3ffe02a3d20e`。默认 prepare 入口与三个副本哈希核验通过，不另签同code，不启动服务/隧道；previous为1.1.7/code18，旧包保留。手机触感需要用户开启系统与应用开关，发布成功不代表实际震感已验收。

2026-10-12 云端发布同步：1.1.7/code18 经 GitHub 原证书构建/代审批/公开复验成功，下载同一 APK 至 `artifacts/device-release-v18/outputs/apk/release/app-release.apk`，同步仓库安装包与元数据/profiles，并通过默认 `python update_server.py --prepare-only` 准备本地清单。APK 为 4,981,397 字节，SHA-256 `294e4391a57f029880e348c8baeb099dbaab16c1eb06b4d64b8f2e790d825675`；云端/代理目录/仓库包/本地备用字节一致，没有为同 code 另行重签，也没有启动本地服务或隧道。旧 APK 保留。新客户端仍固定走 GitHub，不需要或提供更新源配置；本地方式仅留给开发者与旧客户端迁移，不能把文件准备成功当作公网可用。

| 现象 | 检查或处理 |
| --- | --- |
| 源码与 APK 版本不符 | 检查实际选中的文件；新版本必须重建。显式指定旧包仍会拒绝发布，不能关闭校验。 |
| 安装失败 -7 / 签名不同 | 确保使用原 `app_sign.jks/key0`。不新建密钥，不先卸载；确需迁移时先做完整备份并另行确认。 |
| 本机正常，手机无法下载 | 检查 Python 进程、4387 监听、SakuraFrp 运行状态和 mcMC 映射，再查公网 TLS 与网络。 |
| 4387 被其他程序占用 | 优先查明占用；不要随意改端口，隧道必须与实际监听一致。 |
| 换电脑后不能解密 | 用原证书在新电脑重新运行交互配置脚本，不能复制明文密码进源码。 |
| 新包校验或构建失败 | 保留旧清单和旧 APK；解决错误后重试未发布版本，不发布 Debug 包。 |

当前 Python 发布器保留旧 APK，但不提供完整的自动部署日志/一键回滚功能。临时撤回需停止发布、恢复已核验的旧清单及其 APK，再核对本机和公网；手机已经安装新版本时，恢复旧清单不会让 Android 自动降级，修复必须发布更高 code 的同签名包。

1.1.2 及更早客户端曾有历史遗留的宽松 TLS 信任逻辑；1.1.3 起已移除。开发本地入口也应使用有效域名证书或已验证的私有网络方案，不能重新全局绕过证书验证。APK 签名校验不等于安全传输。详细构建规则见 [真机验收构建与在线更新交付](qa/device-release-workflow.md)。
